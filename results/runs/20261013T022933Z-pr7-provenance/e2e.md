# 端到端对比：H2D + 变换 + D2H（自研 vs CANN 原生 vs 裸 CANN C API）

> 硬件 Ascend910_9382（48 AIV）；reps=10；`--rounds 3` 逐点 min-of-means（与 `matrix_test.py` 同口径）。

**口径**（三路逐段对应，计时区外均剔除进程/框架启动与输入生成）：
1. `自研` = H2D → `kfft_fwd` → D2H（复数→复数，`fft_check AB_E2E=1`）
2. `原生` = `xd.copy_(x_cpu)` → `torch.fft.fft(xd)` → `yd.copy_(out)`（源/目的均 pinned）（复数→复数，torch_npu op-plugin 内核）

3. `裸 CANN` = H2D → `aclRfft1D` → D2H（**实→复、单边**，唯一可用的裸 CANN C API FFT —— CANN 9.0.0 没有复数→复数 C API）

 
**表1 的 `E2E 比值 > 1` 表示自研更快**；只算 kernel 的 `device 比值` 见 `matrix_test_a7.md`。
**表2 仅作参照、不参与胜负统计**：
* 变换不同（实→复 vs 复→复），且 **搬运量正好是一半**（`8n·B` vs `16n·B` 字节），大 batch 的 E2E 不可直接比；
* 它的价值在 **device-only**：与传输无关，用来把「CANN 算子调用路径的固定开销」和「torch 调度 + op-plugin」分开。

## 汇总

- 正确性：**49/49 PASS**（maxRel ≤ 1e-4）
- **device-only**：47/49 点自研更快，几何均值 1.64x
- **端到端 E2E**：47/49 点自研更快，几何均值 1.44x
- **裸 CANN `aclRfft1D`**（实→复，仅参照，49/49 点）：device 几何均值 **187.4 µs**、E2E 几何均值 **288.9 µs**；`原生 device ÷ 裸 device` 几何均值 **0.68x**（两路变换不同，只看固定开销量级）
  - 小 batch（`B ≤ 64`，传输可忽略）：裸 device **163.2 µs** vs 原生 **98.7 µs** vs 自研 **53.2 µs** —— 固定开销在 CANN 调用路径本身，不是 torch 层
- E2E 最快点 **1.83x** @ n=64/b=16，最慢点 **0.96x** @ n=1024/b=4096
- 逐轮原始计时/状态记录（每 round、每方一行，含 PASS/FAIL 与 maxRel）：同目录 `e2e.raw_rounds.csv`，并在 JSON 的 `raw_rounds` 字段内。
