# 当前实验范围的定向性能收敛

本轮不再扩大长度、batch、精度或算子范围。目标是在当前发布快照
`ascend910_9382-revalidation-20261010` 已声明的 C2C、R2C 和 C2R 网格内，处理所有相对匹配
NPU 基线低于 `1.0x` 的点，然后结束这一轮 Ascend 迁移验证。目标清单由
[`config/convergence_targets.json`](https://github.com/TruNcat3/ascend-fft/blob/master/config/convergence_targets.json) 固定，并由
`python3 scripts/check_convergence_targets.py --check` 从发布快照反向校验；不能通过删点、修改
parity 区间或更换基线让目标消失。

这里区分两个判据：结果页继续用 `0.95x..1.05x` 表示统计上的“接近持平”，但本轮逐点收敛目标
是严格的 `speedup > 1.0x`。因此 R2C 中两个位于 parity 区间、但仍低于 `1.0x` 的点也进入任务。

## 实施顺序

### 0. 复现与冻结

1. 从本 PR 的最终 merge commit 构建，运行 `scripts/init.sh --check` 和硬件 profile 检查。
2. 用原快照相同的精度、方向、归一化、placement、warmup、repeat 和计时区间复测 14 点。
3. 保存原始 trial、执行顺序、正确性、当前选型和基线版本。若复测方向与快照不一致，先解释
   环境或测量漂移，不立即调参。

### 1. 建立定向 runner

新增一个读取 `config/convergence_targets.json` 的 runner。每个语义点必须同时运行：

- 当前发布配置，即 incumbent；
- 模型选出的有限候选；
- 在预声明预算内实测的候选；
- 同语义外部基线。

候选集合必须包含 incumbent。选择器只能晋升通过正确性门禁、且在同一协议下稳定快于 incumbent
的配置；否则回退 incumbent。输出至少包含 `transform,N,batch,candidate_id,mapping,processing_unit,
correct,error,latency,baseline_latency,incumbent_latency,selection_reason`。

### 2. 按症状搜索，不做全空间暴力枚举

先为 A/B/C 各选一个代表点做轻量 profile，再决定扩大哪一类轴。优先顺序如下：

1. **架构映射**：AIV 数、batch/data 的空间与时间展开、每核工作量、tile/K、尾部处理；
2. **数据流与布局**：实数半谱打包/展开、GM 连续性、UB 排布、搬运粒度和必要的双缓冲；
3. **计算核心选型**：radix、阶段融合、twiddle 处理及 R2C/C2R 的局部核心；
4. **驻留与流水**：仅在计数或 trace 证明搬运/等待是瓶颈时尝试，不把 pp2 研究路径直接设为默认。

架构映射与计算核心选型相互正交：可以在不改变计算公式的前提下重排工作流，也可以在同一工作流
中替换更好的局部核心。配置文件中存在但 kernel 未消费的参数不得进入候选。所有搜索轴都必须通过
lowering/resource contract，且保存实际使用的配置，而不是只保存候选名称。

### 3. 固化逐点选择

将胜出的点写入带硬件、CANN、kernel 和模型版本的静态 dispatch 表。未命中的尺寸继续走模型或
有限搜索并打印选择来源；不能用某个 shape 的硬编码分支绕过统一 plan/selector。静态表只缓存
已验证决策，硬件 profile 或实现版本变化时必须失效并重新校准。

### 4. 全矩阵回归与发布

定向点通过后，重新运行完整 C2C 49 点、R2C 49 点、C2R 49 点、端到端和应用 shape。只有完整矩阵
无正确性回退、无 incumbent 回退，才能发布新的不可变快照并更新图表。不得只提交 14 个胜出点。

## 验收门槛

| 门禁 | 必须满足 |
|---|---|
| Correctness | 每个 trial 通过现有误差契约；失败样本不得进入 timing 汇总 |
| 候选晋升 | 相对 incumbent 的 median 至少提升 2%，否则保留 incumbent |
| 逐点目标 | 14 个目标相对匹配 NPU 基线的 median 全部大于 `1.0x`；优先争取 `>=1.05x` |
| 稳定性 | 至少 5 个独立 trial，报告 median、p10、p90、CV 和逐 trial 原始值 |
| 闭包 | 搜索/模型候选显式包含 incumbent，选择后结果不得低于当前发布配置 |
| 非回退 | 完整 C2C/R2C/C2R 网格正确，既有正收益点不得因新默认配置变慢 |
| 可复现性 | 新快照绑定 clean commit、硬件/CANN 身份、命令、二进制哈希和原始数据 |

若有限预算内仍有点不能超过 `1.0x`，应保留原始证据并标为 unresolved，说明是计算核心、数据流、
传输还是基线特化造成；这不允许被几何均值掩盖，也不应触发无边界的新功能扩展。

## 本轮明确不做

- 不新增精度、非二次幂、2D、stride 或其他 SoC；
- 不以 CPU 基线替代同卡 NPU 基线；
- 不要求把实验 pp2 路径推广为生产默认；
- 不以追平全世界所有 FFT 库为退出条件；
- 不通过扩大有利样本来改变当前 14 点的结论。

本轮完成后，仓库即可按“cuButterfly 方法在 Ascend 上的可复现迁移实例”收敛。后续能力扩展继续
保留在[未来计划](../roadmap.md)，但不阻塞本轮发布。
