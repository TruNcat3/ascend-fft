## 阅读原则

当前设计主线是：**依赖与 Roofline → 计算流问题 → 阶段/数据空间-时间映射 → 局部计算核心
选型 → lowering contract → profile/search**。每轮优化都应分别记录 flow 变量、core 变量及
二者的交互；不能把某个 radix、向量指令或 Cube 单元的局部收益直接写成范式收益。最简洁的
判断句是：

这条分析主线及其详细推导、设计判断和实验归因原则来自
[cuButterfly](https://github.com/TruNcat3/cuButterfly)；Ascend-FFT 记录的是它在 Ascend
硬件上的迁移、重新 lowering 和验证结果。

> 我们优化的是“数据如何流经局部计算”，不是宣称重新发明“局部计算是什么”；二者可组合，
> 收益必须在相同协议下拆分归因。

详细的动机、架构边界和核心选型分别见[设计动机](design/motivation.md)、[架构与映射](design/architecture.md)
和[计算核心](design/kernels.md)。
