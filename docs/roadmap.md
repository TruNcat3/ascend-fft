# 未来计划与验收

Ascend-FFT 的目标是面向不同精度、长度、batch 和 Ascend 硬件生成合适的 FFT 执行计划，
而不是把当前验证范围固化为库的定义。本页按依赖关系列出后续工程与研究工作；它不是发布承诺，
也不将尚未实现的路径写成已有能力。当前可用接口以[支持范围](reference/support.md)为准。

继续沿用 [cuButterfly](https://github.com/TruNcat3/cuButterfly) 的方法分层：
架构映射描述阶段/数据的空间与时间组织，计算核心选型描述蝶形算术，lowering 契约负责硬件合法性。
新增能力必须同时补齐执行实现、模型计数和验收证据，不能只扩大配置文件中的候选列表。

## 推进顺序

| 阶段 | 主要问题 | 退出条件 |
|---|---|---|
| 近期工程闭环 | 选型、执行和结果发布是否可信、可复用 | profile、计划缓存与自动验证形成闭环 |
| 中期算子能力 | FFT 接口与语义覆盖是否完整 | 每种新增语义有独立契约与正确性门禁 |
| 性能研究 | 映射与核心选择为什么有效、在哪里失效 | 模型、消融和计数器形成可复核证据 |
| 跨硬件验证 | 方法可迁移与参数可复用是否被区分 | 新硬件重新探测、校准并完成留出测试 |
| 发布验收 | 文档与性能结论是否对应同一实现 | 固定协议、快照和回归检查全部通过 |

各阶段可以交叠，但不能用后续的理论目标替代当前的实验结果。

## 1. 近期工程闭环

### 自动硬件 profile 与模型版本化

- **当前缺口**：已有硬件探针和校准工具，但安装尚不能自动完成审核、校准与留出验证；
  profile 含历史字段，成本系数与实现仍需要人工同步。
- **交付内容**：统一的 probe → 约束审核 → 典型微基准 → 系数校准 → 留出验证入口；
  保存 SoC、CANN、编译器、kernel/模型版本与来源，并拒绝不兼容的旧表。
- **验收证据**：从干净环境重建 profile 的日志；约束与边界测试；未参与校准的
  长度/batch 上的预测误差、排序命中率和相对实测最优的选择损失。

### 可复用执行 API 与计划缓存

- **当前缺口**：公开 API 使用 host 指针并同步完成传输；Context 固定设备 0，缺少
  用户 stream、device-pointer 和稳定 C ABI。已有 Plan 复用不等于完整异步执行契约。
- **交付内容**：先定义设备选择、缓冲区所有权、workspace、stream 和生命周期；
  增加 device-pointer 执行路径与计划缓存，保留现有同步 host API；再提供稳定 C ABI。
- **验收证据**：新旧 API 同结果、重复执行与销毁测试、异步完成/错误传播测试；分别报告
  建计划、首次执行和稳态执行成本，不将传输移出计时区间解释成 kernel 加速。

### 结果流水线与回归矩阵

- **当前缺口**：发布器和结果快照已有基础，但历史实数数据缺少新版逐行正确性字段；
  当前完整网格也不是全部合法输入的穷举。
- **交付内容**：用现行协议重采 C2C/R2C/C2R，统一记录候选、误差、重复次数、计时区间和
  manifest；将功能门禁、快速性能回归和完整发布矩阵分开。
- **验收证据**：每个发布点有正确性记录与原始样本；摘要、图表和 README 来自同一快照；
  失败点明确呈现，生成物 freshness 和文档链接检查自动通过。

## 2. 中期算子能力

### 完整变换语义

- **当前缺口**：公开 C2C 仅前向；R2C/C2R 已有实现，但方向与归一化尚未统一成完整 API。
- **交付内容**：逆向 C2C、明确的 normalization 选项、实数半谱约束与方向切换行为。
- **验收证据**：与同语义参考库逐点比较，覆盖冲激、常量、随机、动态范围与 Nyquist 边界；
  加入 round-trip 和缓存方向切换测试，按精度给出误差标准。

### 更广长度、布局与维度

- **当前缺口**：当前生产路径以单 AIV 的 UB 容量和稠密 1D 二次幂输入为边界；
  任意 stride、非二次幂和 2D/多维尚未形成公开路径。
- **交付内容**：先扩展分段长 FFT 与 2D 行列映射，再按需求引入 stride 与非二次幂算法候选。
  padding 必须作为显式的应用选项：补零改变变换长度，不能冒充原长度 DFT。
- **验收证据**：UB 临界点、分段交接、矩形 2D、非连续布局和不同长度类型的正确性测试；
  包含重排/转置与 workspace 的完整计时，并保持基线语义一致。

### 更多精度与计算核心

- **当前缺口**：公开实现仅验证 fp32；`pointSize==2` 是当前 Plan 装载边界，
  局部 radix-4 融合不等于任意 radix 的独立后端。Cube 目前只是探针。
- **交付内容**：按硬件实际能力新增精度/累算策略、radix 与核心选项，每项声明布局、UB、
  对齐与同步契约；Cube 路径在具备完整 lowering 后才进入候选池。
- **验收证据**：精度误差与溢出/动态范围测试、非法配置拒绝测试、相同架构点的核心 A/B；
  未有生产实现或实测收益的选项继续标记为研究路径。

## 3. 性能研究

### 映射参数与性能拐点

- **当前缺口**：已有 K、batch 折叠和核数选型，但理论参数空间与可执行 envelope 仍有差别；
  当前证据不能说明所有长度与 batch 的最优映射。
- **交付内容**：按阶段/数据空间时间划分、布局与驻留策略组织消融；分析启动主导、活跃核不足、
  UB 容量和稳态吞吐的拐点，保存每个点的模型选择与实测最佳候选。
- **验收证据**：固定 workload 网格上的 latency/speedup 图、配置偏好图和选择损失；
  展示胜出与落后点，而不是扩大有利样本后只比较几何均值。

### 搬运与计算重叠、驻留子图

- **当前缺口**：当前 transform 的中间值已在单 AIV UB 中，但这不证明 MTE 与计算完全重叠；
  跨 AIV 独立阶段角色和 AIC/AIV 联合 FFT 尚无生产实现。
- **交付内容**：先以双缓冲、预取和单核时间遍历做受控实验，再评估跨核驻留子图与角色交接；
  将额外 GM 流量、同步和缓冲容量纳入可行性与成本模型。
- **验收证据**：trace 中的实际重叠区间、GM/UB 搬运量、等待与尾部时间；
  与无重叠实现同协议比较。只有净收益通过重复测量后才升级为默认候选。

### 模型泛化与专业库对比

- **当前缺口**：现有校准网格与已验证硬件不能证明跨算子/硬件泛化，device-only 与端到端优势也不同。
- **交付内容**：独立校准集/验证集，比较模型选型、有限搜索与固定配置；扩展同卡专业库、
  实数变换和真实应用 shape 的基线矩阵。
- **验收证据**：模型排序与误差分布、搜索成本、稳态性能和最差选择损失；同语义、同精度、
  同计时口径的胜/平/负点数与完整矩阵。跨 GPU 公开数据仅作背景参照。

## 4. 跨硬件验证

- **当前缺口**：当前发布证据来自 Ascend910_9382 / CANN 9.0.0；修改 `AB_SOC`
  或加载同名 JSON 不等于迁移完成。
- **交付内容**：为新 SoC 重新探测 AIV/AIC、UB、MTE、对齐与指令 envelope，建立设备专属
  profile/模型表；在相同方法参数下实现合法 lowering，保留原硬件配置作对照。
- **验收证据**：每台设备独立的 probe、正确性、留出选型与性能报告；明确哪些参数改变、
  哪些方法不变。不得把一台卡的 speedup 或系数直接外推到其他硬件。

## 5. 发布验收

能力从“研究选项”进入发布支持范围前，应同时完成：

1. 可查询的合法性与执行契约，拒绝未消费或未实现的参数组合。
2. 单元/边界/数值正确性与[五道门禁](development/validation-and-release.md)。
3. 独立的模型或候选选型证据，保存已验证配置与来源。
4. 固定协议的重复测量、误差、基线和完整原始数据，生成可复现图表。
5. 更新 API、支持矩阵、故障排查、快照及 cuButterfly 来源/引用声明。

性能目标是减少可解释的选择损失与执行开销，不预先承诺全面超过专业库。
每轮迭代都应报告“新增能力、实际收益、仍然落后的点”，再确定下一轮优先级。
